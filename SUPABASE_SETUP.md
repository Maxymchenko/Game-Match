# Game-Match — інструкція з налаштування нового Supabase-проєкту

Цей документ призначений для людини, яка створює **новий Supabase-проєкт** для застосунку Game-Match і підключає його до наявного коду.

## 1. Що потрібно отримати від власника проєкту

Перед початком попросіть власника надати:
- доступ до репозиторію/папки з кодом Game-Match;
- Twitch Developer credentials для IGDB: `TWITCH_CLIENT_ID` та `TWITCH_CLIENT_SECRET`;
- адресу розгорнутого фронтенду (production URL), якщо застосунок уже опублікований.

Не просіть надсилати секрети в чаті або додавати їх у вихідний код. Власник має вводити секрети безпосередньо в Supabase Dashboard або в локальний захищений термінал.

## 2. Створити Supabase-проєкт

1. Відкрити https://supabase.com/dashboard і увійти у свій обліковий запис.
2. Створити Organization, якщо її ще немає.
3. Натиснути **New project**.
4. Вказати назву, наприклад `game-match`, надійний пароль бази даних і найближчий відповідний регіон.
5. Зберегти пароль бази даних у менеджері паролів. Він не потрібен фронтенду.
6. Дочекатися завершення створення проєкту.

У Dashboard → **Project Settings → API** (або розділ API Keys у новому інтерфейсі) знайти:
- **Project URL**;
- **Publishable key** (або legacy **anon** key).

Для браузерного застосунку використовується лише publishable/anon key. **Ніколи не вставляти service_role/secret key у Vite, React або будь-який файл з префіксом `VITE_`.**

## 3. Застосувати схему бази даних

У репозиторії вже є готова міграція:

`supabase/migrations/202611150001_initial_schema.sql`

Вона створює:
- `profiles` — профілі користувачів;
- `preferences` — обрані платформи, жанри, бюджет, підписки та ліміт ціни;
- `library_entries` — персональна бібліотека ігор та їхні статуси;
- функцію та тригери оновлення `updated_at`;
- тригер створення профілю після реєстрації;
- індекси та Row Level Security (RLS) політики, що обмежують доступ власними записами.

### Варіант A — через Supabase Dashboard

1. Відкрити новий проєкт → **SQL Editor**.
2. Відкрити файл `supabase/migrations/202611150001_initial_schema.sql` у коді Game-Match.
3. Скопіювати весь SQL у новий SQL query.
4. Натиснути **Run**.
5. Перевірити в **Table Editor**, що з'явилися таблиці `profiles`, `preferences`, `library_entries`.

### Варіант B — через Supabase CLI (рекомендовано для подальших міграцій)

У терміналі, з кореневої папки Game-Match:

```powershell
npx supabase login
npx supabase link --project-ref YOUR_NEW_PROJECT_REF
npx supabase db push
```

Якщо CLI повідомляє, що локальний проєкт не ініціалізований, перевірити наявність `supabase/config.toml`; він уже входить до цього проєкту. Не запускати повторно `supabase init` поверх наявної конфігурації.

Після застосування міграції перевірити таблиці в Table Editor.

## 4. Налаштувати Authentication

У Supabase Dashboard відкрити **Authentication → URL Configuration**:

- **Site URL**: URL production-сайту. Для локальної розробки можна тимчасово використовувати `http://localhost:5173`.
- **Redirect URLs**: додати URL локального застосунку `http://localhost:5173/**` та production URL із відповідним wildcard, наприклад `https://your-domain.example/**`.

У **Authentication → Providers → Email**:
- переконатися, що Email provider увімкнений;
- погодити з власником, чи має бути ввімкнене підтвердження email;
- якщо підтвердження увімкнене, перевірити шаблон листа та Redirect URL.

Не вимикати email confirmation без погодження з власником. Для тестування використовувати окремі тестові облікові записи.

## 5. Налаштувати IGDB Edge Function

У коді є функція:

`supabase/functions/igdb/index.ts`

Вона:
- вимагає автентифікований Bearer token користувача;
- перевіряє сесію через Supabase Auth;
- отримує Twitch access token серверним способом;
- запитує каталог ігор IGDB;
- підтримує популярні ігри з offset та пошук;
- повертає дані гри, платформи, жанри, теми, ключові слова та перспективу гравця.

У `supabase/config.toml` для функції встановлено `verify_jwt = true`. Залишити цю перевірку увімкненою.

### Додати секрети функції

У Supabase Dashboard → **Edge Functions → Secrets** додати:

| Назва | Значення |
|---|---|
| `TWITCH_CLIENT_ID` | Client ID із Twitch Developer Console |
| `TWITCH_CLIENT_SECRET` | Client Secret із Twitch Developer Console |
| `APP_ORIGIN` | Production URL фронтенду; для локальної розробки — `http://localhost:5173` |

`APP_ORIGIN` використовується для CORS. Якщо є і локальна, і production-версія, узгодити потрібний origin з власником і налаштувати його відповідно до середовища розгортання. Поточна функція приймає один origin через `APP_ORIGIN`.

Supabase зазвичай надає функції системні змінні `SUPABASE_URL` та ключ publishable/anon автоматично. Не задавати їх вручну без потреби та не додавати service role key у клієнтський код.

### Розгорнути функцію

З кореня Game-Match виконати:

```powershell
npx supabase functions deploy igdb --project-ref YOUR_NEW_PROJECT_REF
```

Переконатися в Dashboard → **Edge Functions**, що `igdb` має статус deployed.

## 6. Підключити фронтенд до нового проєкту

У корені Game-Match створити локальний файл `.env` на основі `.env.example`:

```powershell
Copy-Item .env.example .env
```

Заповнити `.env` значеннями з нового Supabase-проєкту:

```env
VITE_SUPABASE_URL=https://YOUR_NEW_PROJECT_REF.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLISHABLE_OR_ANON_KEY
```

У цьому проєкті клієнт читає саме ці дві змінні у файлі `src/api/supabase.ts`.

Важливо:
- `.env` не комітити й не передавати публічно;
- `.env` уже виключений із Git через `.gitignore`;
- не додавати Twitch secret або service role key до `.env` фронтенду;
- після зміни `.env` перезапустити Vite dev server.

## 7. Перевірити роботу

З кореня проєкту:

```powershell
npm install
npm run lint
npm run build
npm run dev
```

Потім перевірити в браузері:

1. Застосунок завантажується без помилки конфігурації Supabase.
2. Реєстрація нового користувача працює.
3. Якщо email confirmation увімкнений — лист підтвердження надходить і посилання повертає на правильний URL.
4. Після входу можна пройти onboarding і зберегти налаштування платформ, жанрів та бюджету.
5. Після перезавантаження сторінки налаштування користувача зберігаються.
6. Запит популярних ігор повертає каталог через Edge Function `igdb`.
7. Пошук ігор через IGDB працює.
8. Додавання гри до бібліотеки, зміна статусу та видалення працюють.
9. Створити два тестові акаунти й перевірити, що кожен бачить лише власні налаштування та записи бібліотеки. Це перевірка RLS і є обов'язковою.

Якщо IGDB повертає помилку, перевірити Edge Function Logs та наявність Twitch secrets. Не виводити секрети у логи.

## 8. Передача результату власнику

Передати власнику:
- новий **Project URL**;
- publishable/anon key для локального `.env` (передати приватно);
- Project Reference ID;
- підтвердження, що міграція застосована;
- підтвердження, що `igdb` deployed;
- результат тестів із розділу 7.

**Не передавати** пароль бази даних, Twitch Client Secret або service role/secret key у відкритому вигляді. Якщо іншій людині потрібен постійний доступ до Dashboard, краще запросити її як члена організації з мінімально необхідною роллю, а не ділитися своїм паролем.

## Примітки та межі

- Ця інструкція створює нову порожню базу. Вона не переносить старі акаунти, профілі чи записи бібліотеки з попереднього Supabase-проєкту.
- Схема описує поточну міграцію в репозиторії; якщо код або міграції зміняться, перед налаштуванням потрібно звірити їхню актуальність.
- Після створення нового проєкту потрібно оновити локальний `.env` і розгорнути Edge Function саме в новий Project Ref.
